Security Advisory: CVE-2025-60479 - NULL Pointer Dereference in GPAC/MP4Box

Processing a crafted MPEG-4 file with broken BIFS vector fields triggers a NULL pointer dereference in `StatSFVec2f`, causing MP4Box to crash during scene statistics collection.

Summary:
The `StatSFVec2f` function in `scene_manager/scene_stats.c` collects statistics for SFVec2f fields in an MPEG-4 BIFS scene. When the scene contains a crafted broken vector field, the statistics traversal passes a NULL pointer to `StatSFVec2f` without validation. The function dereferences the pointer at address 0x0, terminating the process with SIGSEGV.

CWE:
CWE-476 - NULL Pointer Dereference

Affected Component:
```
scene_manager/scene_stats.c:192
Function: StatSFVec2f()
```

Affected Product:
MP4Box (GPAC Multimedia Open Source Project)

Affected Version:
2.5-DEV-rev1678-gb7ffd9f96-master; commit `b7ffd9f96bc188dde148300d8c4e510b557563aa`. Any codebase equivalent to this commit that has not applied the fix commit is affected.

Attack Conditions:
An attacker supplies a crafted MPEG-4 file containing a malformed BIFS scene with invalid SFVec2f vector field structures. Local access is required; the victim must invoke `MP4Box -nstat <crafted_file>` or any equivalent scene statistics command that triggers the scene analysis path.

Impact:
The NULL pointer dereference (READ at address 0x000000000000) causes an immediate process crash, resulting in Denial of Service. No evidence of arbitrary code execution was observed; the faulting access is a NULL read that is not exploitable for control-flow hijacking.

Fix / mitigation status:
The issue was fixed in GPAC commit:
```
75786eb61b7cc838b57c3d4f8004b4f13b5b724c
```
Users should update to a GPAC build containing this commit or later.

Security Advisory: CVE-2025-60491 - Use-After-Free in GPAC/MP4Box

Processing a crafted MPEG-2 TS file with corrupted PMT descriptors triggers a heap use-after-free in `dasher_flush_segment`, causing MP4Box to crash during DASH segmentation.

Summary:
The `dasher_configure_pid` function in `filters/dasher.c` frees a PID context structure at line 986 when reconfiguring a stream from a crafted MPEG-TS input. The freed pointer is not nullified, and `dasher_flush_segment` subsequently reads 4 bytes at offset 336 within that freed 1096-byte region at line 8062 during the segment flush cycle, constituting a heap-use-after-free.

CWE:
CWE-416 - Use After Free

Affected Component:
```
filters/dasher.c:8062
Function: dasher_flush_segment()
```

Affected Product:
MP4Box (GPAC Multimedia Open Source Project)

Affected Version:
2.5-DEV-rev1698-gfc2009fa7-master; commit `fc2009fa75631960743f8f7855dda8998167b5ab`. Any codebase equivalent to this commit that has not applied the fix commit is affected.

Attack Conditions:
An attacker supplies a crafted MPEG-2 TS file containing broken PMT descriptor sizes, reused PIDs, and sync marker violations. Local access is required; the victim must invoke `MP4Box -dash 1000 <crafted_file>` or any equivalent DASH segmentation command that triggers PID reconfiguration in the dasher module.

Impact:
The use-after-free (READ of size 4 at 336 bytes into a freed 1096-byte heap region) causes process termination, resulting in Denial of Service. Code execution cannot be ruled out; use-after-free vulnerabilities allow an attacker to control freed memory contents and potentially redirect execution flow.

Fix / mitigation status:
The issue was fixed in GPAC commit:
