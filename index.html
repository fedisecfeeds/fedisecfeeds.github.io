🎯 Threat Intelligence: PHP2Shell Exploitation on Check Point Gateways
===================

Check Point Research reports scanning and exploitation against unpatched Security Gateways beginning on October 30, 2026. In one investigated intrusion, attackers used vulnerable Mobile Access portals for initial access, escalated to root and subsequently reached a VMware ESXi host where a wiper was deployed.

The first wave targeted Israeli organizations and included destructive activity against some victims. A second wave on November 2 targeted organizations in multiple countries and sectors, including some previously targeted in Israel. The researchers found no evidence of destructive activity in that second wave.

🔹 Attack Chain Analysis

🎣 Initial Access: Activity consistent with PHP2Shell targeted Mobile Access portals. The report associates PHP2Shell with CVE-2026-109618 and CVE-2026-109619. The first observed activity originated from 130.94.19[.]204, approximately one week after a security fix became available.

🛡️ Privilege Escalation: In the investigated intrusion, the attacker moved from the portal service account to root through CVE-2026-123039, a local privilege-escalation vulnerability in the DynamicCLI IPC interface.

🦠 Persistence: Privileged command execution was used to deploy PHP webshells and the persistent TSGA backdoor. TSGA includes the TSProxy networking component.

🎯 Lateral Movement: The attacker pivoted from the gateway to a VMware ESXi host over SSH.

🔒 Destruction: The attacker deployed the destroy_v6 wiper and left politically themed DREAM_ANNEXATION.txt notes.

🔹 Artifacts and detection context

The report describes PHP session artifacts under /opt/CPcvpn-R81.20/tmp/, including files containing the upload_progress_pwn marker. Apache/PHP workers on the affected portal also experienced hundreds of segmentation faults during the exploitation window. These observations are associated with the reported activity; the provided excerpt does not establish that either artifact is unique to this campaign.

The source names the PHP webshells, TSGA, TSProxy, destroy_v6 and the note file as additional artifacts. It does not provide hashes, detection rules or complete network indicators in the supplied text.

🔹 Malware relationship and attribution

TSGA and TSProxy are modified variants of PhiliKit, a framework previously documented in attacks exploiting Ivanti vulnerabilities. Check Point reports shared code, configuration and cryptographic material. ESET previously associated PhiliKit with China-nexus UNC5221, but the researchers do not attribute this complete operation with high confidence.

Several explanations remain possible: the identified actor ran the campaign, acted only as an initial access broker, or was involved in a false-flag operation. The destructive activity might also have served as a smoke screen. The note uses the Dream Security brand; its timing relative to Dream's earlier PHP2Shell research does not establish retaliation as a motive.

🔹 Mitigation and references

The report says a security fix was available approximately one week before the initial activity. The supplied excerpt does not specify patch versions or provide a complete remediation procedure.

Check Point Research reports scanning and exploitation against unpatched Security Gateways beginning on October 30, 2026. In one investigated intrusion, attackers used vulnerable Mobile Access portals for initial access, escalated to root and subsequently reached a VMware ESXi host where a wiper was deployed.

The first wave targeted Israeli organizations and included destructive activity against some victims. A second wave on November 2 targeted organizations in multiple countries and sectors, including some previously targeted in Israel. The researchers found no evidence of destructive activity in that second wave.

🔹 Attack Chain Analysis

🎣 Initial Access: Activity consistent with PHP2Shell targeted Mobile Access portals. The report associates PHP2Shell with CVE-2026-109618 and CVE-2026-109619. The first observed activity originated from 130.94.19[.]204, approximately one week after a security fix became available.

🛡️ Privilege Escalation: In the investigated intrusion, the attacker moved from the portal service account to root through CVE-2026-123039, a local privilege-escalation vulnerability in the DynamicCLI IPC interface.

🦠 Persistence: Privileged command execution was used to deploy PHP webshells and the persistent TSGA backdoor. TSGA includes the TSProxy networking component.

🎯 Lateral Movement: The attacker pivoted from the gateway to a VMware ESXi host over SSH.

🔒 Destruction: The attacker deployed the destroy_v6 wiper and left politically themed DREAM_ANNEXATION.txt notes.

🔹 Artifacts and detection context

The report describes PHP session artifacts under /opt/CPcvpn-R81.20/tmp/, including files containing the upload_progress_pwn marker. Apache/PHP workers on the affected portal also experienced hundreds of segmentation faults during the exploitation window. These observations are associated with the reported activity; the provided excerpt does not establish that either artifact is unique to this campaign.

The source names the PHP webshells, TSGA, TSProxy, destroy_v6 and the note file as additional artifacts. It does not provide hashes, detection rules or complete network indicators in the supplied text.

🔹 Malware relationship and attribution

TSGA and TSProxy are modified variants of PhiliKit, a framework previously documented in attacks exploiting Ivanti vulnerabilities. Check Point reports shared code, configuration and cryptographic material. ESET previously associated PhiliKit with China-nexus UNC5221, but the researchers do not attribute this complete operation with high confidence.

Several explanations remain possible: the identified actor ran the campaign, acted only as an initial access broker, or was involved in a false-flag operation. The destructive activity might also have served as a smoke screen. The note uses the Dream Security brand; its timing relative to Dream's earlier PHP2Shell research does not establish retaliation as a motive.

🔹 Mitigation and references

The report says a security fix was available approximately one week before the initial activity. The supplied excerpt does not specify patch versions or provide a complete remediation procedure.
