Security Advisory: CVE-2025-60482 - Use-After-Free in GPAC MP4Box AC-4 Descriptor Cleanup

Processing a crafted AC-4 stream with MP4Box can trigger a heap use-after-free in `gf_odf_ac4_cfg_clean_list()`.

Summary:
The recursive AC-4 descriptor cleanup path can revisit or count a list object that has already been freed. When MP4Box imports a crafted AC-4 input, descriptor destruction reaches `gf_odf_ac4_cfg_clean_list()` and then `gf_list_count()` on stale heap memory.

AddressSanitizer reports `heap-use-after-free`.

CWE:
CWE-416 - Use After Free

Affected Component:
```
odf/descriptors.c:2411
Function: gf_odf_ac4_cfg_clean_list()

utils/list.c:664
Function: gf_list_count()
```

Relevant ASAN stack:

```
gf_list_count utils/list.c:664
gf_odf_ac4_cfg_clean_list odf/descriptors.c:2411
gf_odf_ac4_cfg_clean_list odf/descriptors.c:2400
dac4_box_del isomedia/box_code_base.c:9218
```

Affected Product:
MP4Box (GPAC Multimedia Open Source Project)

Affected Version:
```
GPAC version: 2.5-DEV-rev1593-gfe88c3545-master
Commit: fe88c3545aadd597b250ccf23271d5d3de50ccc8
```

Attack Conditions:
An attacker supplies a crafted AC-4 file that is imported by MP4Box:

```
./MP4Box -add 46_gf_odf_ac4_cfg_clean_list_odf_descriptors_c_2411 -new /dev/null
```

Impact:
The observed impact is Denial of Service. Because the bug is a heap use-after-free, memory corruption risk is also present.

Fix / mitigation status:

```
e02d1fd24cdc26acb1b236ab38b3832cffcae21b
```

Security Advisory: CVE-2025-60480 - Heap Buffer Overflow in GPAC MP4Box AC-4 Alternative Info Parsing

A heap buffer overflow vulnerability exists in GPAC MP4Box when processing a crafted AC-4 stream. The issue occurs in `gf_odf_ac4_cfg_alternative_info()` in `odf/descriptors.c` and can be triggered by running MP4Box with the `-info` option on a malformed input file.

Summary:
AddressSanitizer confirms a heap-buffer-overflow at `odf/descriptors.c:1899`. The vulnerable code reads 1 byte past the end of an allocated buffer due to insufficient bounds checking of AC-4 `alt_group_id` array indexes.

The crafted AC-4 stream reaches AC-4 descriptor generation and causes `gf_odf_ac4_cfg_alternative_info()` to access `alt_group_id` data outside the bounds of an allocated buffer. The allocation originates while parsing the raw AC-4 frame, and the out-of-bounds read occurs later while writing AC-4 descriptor information.

Security Advisory: CVE-2025-60494 - NULL Pointer Dereference in GPAC/MP4Box

Processing a crafted MP4 file triggers an invalid memory read in `gf_props_equal_internal` during PID property comparison, causing MP4Box to crash.

Summary:
The `gf_props_equal_internal` function in `filter_core/filter_props.c` compares PID property values using `memcmp`. When importing a crafted MP4 file, the property comparison path at line 867 passes an invalid pointer as one of the `memcmp` arguments; the resulting read-access violation at address 0x11166094 crashes the process with SIGSEGV before the comparison completes.

CWE:
CWE-476 - NULL Pointer Dereference

Affected Component:
```
filter_core/filter_props.c:867
Function: gf_props_equal_internal()
```

Affected Product:
MP4Box (GPAC Multimedia Open Source Project)

Affected Version:
2.5-DEV-rev1699-g31becc9e0-master; commit `31becc9e08b88e525a4a62013a4000de1c0f8fd9`. Any codebase equivalent to this commit that has not applied the fix commit is affected.

Attack Conditions:
An attacker supplies a crafted MP4 file containing invalid or truncated ODF descriptors and box structures. Local access is required; the victim must invoke `MP4Box -add <crafted_file>` or any equivalent import command that triggers PID property initialisation and the property comparison path.

Impact:
The invalid memory read (SEGV READ at address 0x000011166094) causes an immediate process crash, resulting in Denial of Service. No evidence of arbitrary code execution was observed; neither MITRE response marks code execution impact for this specific vulnerability.

Fix / mitigation status:
The issue was fixed in GPAC commit:
```
fcb9083292befe61d3e2466b18edfedba49da098
```
Users should update to a GPAC build containing this commit or later.

Security Advisory: CVE-2025-60496 - Divide by Zero in GPAC/MP4Box

Splitting a truncated MP4 file with uninitialized stream parameters triggers a divide-by-zero in `reframer_send_packet`, causing MP4Box to crash with SIGFPE.

Summary:
The `reframer_send_packet` function in `filters/reframer.c` computes split boundaries using stream parameters such as timescale and estimated file size. When upstream parsing of a truncated MP4 leaves these values uninitialized (zero), the arithmetic at line 1026 performs a division by zero, raising SIGFPE and terminating the process immediately.

CWE:
CWE-369 - Divide By Zero

Affected Component:
```
filters/reframer.c:1026
Function: reframer_send_packet()
```

Affected Product:
MP4Box (GPAC Multimedia Open Source Project)

Affected Version:
2.5-DEV-rev1780-g50b5741f2-master; commit `50b5741f291126b610c59db433fc02e8a17f0c5d`. Any codebase equivalent to this commit that has not applied the fix commit is affected.

Attack Conditions:
An attacker supplies a truncated MP4 file that causes the ISO media parser to leave stream parameters (timescale, file size estimate, or sample rate) at zero. Local access is required; the victim must invoke `MP4Box -split-size 8000 <crafted_file>` or any equivalent split command that triggers the reframer size-estimation path.

Impact:
The divide-by-zero (SIGFPE) causes an immediate process crash, resulting in Denial of Service. No evidence of arbitrary code execution was observed; floating-point exceptions of this type are not exploitable for control-flow hijacking.

Fix / mitigation status:
The issue was fixed in GPAC commit:
```
f03c946aae129980f0426d4cbae9746d0536fee6
```
Users should update to a GPAC build containing this commit or later.
