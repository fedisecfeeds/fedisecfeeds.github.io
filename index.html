The programming mistake behind CVE-2026-119618 is C, but not C.

Had the code used malloc/free(), all would have been fine. But Apache httpd‘s runtime uses its own memory pools. These are not thread safe:

If you allocate memory from two threads you can corrupt the pools. Just via the allocate calls alone.

The pools are kept internally in several data structures and not visible in calls. Modify the „wrong“ hashtable and things explode under load.

The programming mistake behind CVE-2026-119618 is C, but not C.

Had the code used malloc/free(), all would have been fine. But Apache httpd‘s runtime uses its own memory pools. These are not thread safe:

If you allocate memory from two threads you can corrupt the pools. Just via the allocate calls alone.

The pools are kept internally in several data structures and not visible in calls. Modify the „wrong“ hashtable and things explode under load.
