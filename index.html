ulldma at 2026-11-17T21:23:14.381Z ##

⚠️ THIS IS NOT A DRILL!
#Java4Shell CVE-2026-114938
If you're running Java based systems on modern x64 CPUs you'll likely need to act.
Calif has discovered an unauthenticated remote code execution (RCE) vulnerability in the OpenJDK's Base64 decoder.

Technically, it's a memory corruption vulnerability and affects the optimized code path of Java's built-in Base64 decoder making use of AVX-512 instructions.
Thus JVMs running on more modern CPUs like AMD EPYC Zen 4 or later and Intel Xeon Ice Lake/Sapphire Rapids/Emerald Rapids and Granite
Rapids are affected by this vulnerability.
Java's built-in Base64 Decoder is used everywhere these days and is especially widely used in combination with untrusted data coming from
HTTP Basic Auth, SAML, Cookies, JWTs, etc.

Calif was able to exploit following popular Java applications without needing authentication:
* Atlassian Confluence + Jira
* Jenkins
* Keycloak (IAM)
* PingFederate (IAM)
and more

Watch them exploiting different applications here:

https://www.youtube.com/watch?v=-EOYmL4UKvs

Fix:
For a complete fix update affected JDKs. (Oracle Critical Security Patch Update from November 17th, CVE-2026-114938)

Mitigation:
Per Calif's blog post the vulnerability can be mitigated by starting affected JVMs on x64 systems with the parameters:

-XX:-UseBASE64Intrinsics

or

-XX:UseAVX=2

(This command-line flag restricts the HotSpot JIT compiler to using AVX2 vector instructions instead of higher instruction sets like AVX-512.)

Read more in Calif's blog post:
https://calif.io/java4shell

🚨 Critical Java4Shell vulnerability allows hackers to remotely execute code in Jira, Confluence, Jenkins, and other major platforms; CVE-2026-114938

Security researchers at Calif have disclosed a critical OpenJDK vulnerability (CVSS 9.2) that could allow unauthenticated attackers to steal sensitive server memory and execute malicious code remotely.

Dubbed Java4Shell, the flaw affects OpenJDK's Base64 decoder. Researchers successfully demonstrated remote code execution against Keycloak, Jira, Confluence, Jenkins, JFrog Artifactory, and PingFederate in their default configurations.

The vulnerability affects supported Java distributions running on certain x86-64 processors with AVX-512 support. Researchers used AI to discover the flaw in approximately one hour and develop a working exploit in two more hours.

Security updates are now available. Administrators are urged to patch immediately or disable the vulnerable Base64 optimization.
